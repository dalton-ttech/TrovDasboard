# 投流报告中心

目的：在手机上快速了解投流结果，再按需要进入完整报告。投流与物流是两个独立业务入口，共用 Trov 品牌和工作区导航。

## 本轮已实现

| 层级 | 呈现内容 | 可执行操作 |
| --- | --- | --- |
| 报告首页 | 最新日报、最新周报、原报告结论、花费、Meta 购买、Meta ROAS、Shopify 本投放订单 | 阅读日报 / 周报、刷新归档 |
| 报告归档 | 时间区间、报告类型、关键结果 | 按日报 / 周报筛选，搜索日期或正文摘要 |
| 报告详情 | 原始 HTML 全文、统计时区、生成时间 | 独立阅读 |

沿用 Trov_ADS 的既有模板：核心结果、账户信息、订单来源、A02 / A03 广告表现、站点漏斗、视频观看进度、库存与变动、Meta 与 Shopify 数量核对。报告内的模块和结论保持原样。

## 数据与更新

- 从 `Trov_ADS/audits/automation/meta-shopify-daily`、`meta-shopify-weekly` 读取报告。
- 仅纳入 `run-manifest.json` 同时标记 `status=ready`、`writes_performed=false` 且能读取数据和 HTML 的报告。
- 卡片指标来自同一目录的 `data.json`；摘要来自 HTML 的 summary 区域；全文直接读取原始 HTML 文件，不提供 PDF 下载。
- 打开应用及点击「刷新归档」时扫描已有产物，扫描请求有 30 秒合并窗口。
- 本轮接入 22 份日报、6 份周报。最新日报区间为 2026-09-03，最新周报为 2026-08-25 至 2026-08-31。
- 继续由 Trov_ADS 原有工作流生成日报和周报，Dashboard 负责呈现。这里没有新建生成任务或调度。

## 统计口径

- 投流报告使用 `America/Los_Angeles`，与物流时间的 UTC 展示分开。
- Meta 购买、购买价值、ROAS 是 Meta 平台归因结果。
- Shopify 本投放订单采用原报告 `campaign_utm_orders`，不等同于店铺全部订单；本投放净销售额采用 `campaign_net_sales`。
- 汇总仅覆盖 A02 / A03。每张卡片对应自己的统计周期，不把日报与周报相加。
- CPA 在没有购买时显示为缺失，不以 0 代替。源数据缺失的指标显示为 —。

## 后续可扩展方向

1. 在日报日期连续且口径一致时增加日级趋势，周报单独展示，避免重叠统计。
2. 将既有报告中的结论、待核查事项提取成结构化字段，支持跨报告跟踪。
3. 如需要跨设备使用，再设计登录、权限、远程服务与文件存储；当前版本为本机工作区。

这些扩展未在本轮启用。
